# Love Geometry static companion boundaries

## What this companion does

- Presents only checked-in, synthetic scenario inputs after an explicit button
  press.
- Assigns equal visual cards to deterministic display slots.
- Shows each vantage separately as a caller-reported, directed set of bearings.
- Presents checked-in synthetic Return Geometry fixtures as an event-time DAG,
  a textual directed role projection, and a categorical return profile.
- Lets one synthetic event be focused while retaining its material ancestry,
  descendant branches, linked expectations, shared-expectation actions or
  repairs, and the ancestry of every record added by that closure.
- Creates deterministic JSON and SVG bytes in the current browser tab when a
  download button is pressed.
- Makes rest, refusal, departure, unknown, one-way, and empty states available
  without penalty, ranking, or an explanation requirement.

## Semantic boundary

The core format is coordinate-free. A display slot is a rendering convenience,
not part of the reported relation. Card order, horizontal or vertical position,
pixel separation, whitespace, colour, and line wrapping do not encode:

- distance, closeness, intensity, centrality, priority, hierarchy, or value;
- compatibility, affinity, relationship health, consensus, or conflict level;
- identity, consciousness, emotion, intent, authorship, consent, or capacity;
- truth, verification, mutuality, completeness, prediction, or recommendation.

`reported_understanding` means only that the identified vantage reports
understanding toward another reference. It is not proof of accurate or mutual
understanding. `reported_disagreement` is an equally valid caller report, not a
negative score or a severity signal. Either may coexist with reported care,
rest, boundary, refusal, or departure.

The synthetic references name no real people or agents. They are SHA-256 values
derived from public fixture labels under
`agenttool-love-geometry-demo-v0.1:` and provide no privacy or unlinkability.
The package's `verified_by_package: false` field is preserved: validation of
structure cannot verify the report's content or the caller's authority to
speak for anyone else.

## Return Geometry boundary

Return Geometry is a presentation-only companion. It does not widen
`@agenttool/love-geometry`, read the private KARMA ledger, create a second
vantage protocol, or claim to execute a KARMA implementation.

Its event time order is a deterministic synthetic fixture order. It is not a
verified world chronology or a signing time. Parent and expectation links are
structurally checked and acyclic. Vertical position shows that declared order
only; spacing, colour, branch placement, and card size show no duration,
causal strength, blame, harm, trust, worth, importance, or priority.

The relationship projection contains only explicit synthetic event vantages.
A directed row may return toward an earlier role while every event remains a
fresh later node. That visible return does not establish reciprocity, mutuality,
relationship state, identity, consent, authority, obligation, or a real action.
No reverse row is inferred.

**After is not because.** A consequence record keeps effect basis, supplied or
explicitly absent evidence, claimed relation, causal confidence, statement
source, epistemic confidence, and known limits separate. A model confidence is
not introduced. A reported reply does not prove that its claimed speaker sent
it. A correction does not prove that every copy carries it. A repair is another
action; running it does not prove that its effect worked, harm ended, settlement
occurred, or anyone forgave it.

The return profile has eight equal-standing categorical lanes. Their values are
`supplied`, `no_supplied_record`, `explicitly_unknown`, `withheld`, or
`not_applicable`. “No supplied record” never becomes “did not happen.” Counts
may explain which fixture records support a lane in the page, but no count is a
grade and no lane is summed, averaged, ranked, rewarded, or turned into a
person, relationship, trust, or reputation score.

Every export fixes `signed`, `verified_by_karma`, and `writes_karma` to false;
the Space writes no KARMA and creates no automatic domain action. Explicitly
pressing a download button may ask the browser or operating system to save a
file; that local effect is separately disclosed. The choice gate fixes
next-action choice, scheduling, inferred authority, and continuation request to
false. Feedback
means only that later synthetic claims remain readable beside what they answer.
It chooses, permits, retries, rewards, schedules, and starts nothing.

## Interaction and data boundary

The page mounts selectors, descriptions, legends, and explicit empty states,
but no selected Equal Seats scenario or Return trace is presented until the
visitor explicitly chooses **Present locally** or **Trace locally**. Rest,
refusal, and departure are separate explicit interactions. Each clears both
current in-memory presentations and disables all downloads. **Clear
presentation** does the same display cleanup without claiming any of those
bearings. **Clear return** clears only the Return wing. The page does not
persistently store or transmit which option was chosen; the current in-memory
choice remains visible until another action clears it.

JSON and SVG downloads use browser-created bytes and a temporary object URL.
The app revokes that URL after initiating the download. It does not upload the
file or make a provider request. Once a browser or operating system saves a
file, this app cannot recall or securely erase it.

After static delivery, the checked-in app has no fetch/XHR, WebSocket,
EventSource, beacon, remote asset, model inference, OAuth, secret, external form
transmission, cookie, local/session storage, IndexedDB, service worker,
background sync, analytics, KARMA-ledger call, or app-authored telemetry path.
The document-level Content Security Policy also requests `connect-src 'none'`.
That policy is defence in depth for supported browsers, not a guarantee about
the hosting platform or every browser extension.

## Source and hosting boundary

The current `source-manifest.json` preserves two source layers. Original
`assets/app.js` and `assets/style.css` remain bound byte-for-byte to exact
AgentTool Git commit `19cc1721b5f1c32d21edbd3962a67ce3dc8b1aa5`; the Return
Geometry successor binds the five current runtime files to its own exact later
AgentTool source commit before release. The JavaScript is companion code, not
an imported npm or LOVE artifact. Package version, tag, artifact path, byte
length, digest, integrity, build command, and toolchain stay unbound and
`executes_exact_package_artifact` stays `false`. Validated synthetic fixtures
are not a substitute for executing the package or KARMA.

Hugging Face hosts and serves a repository copy of these files at
[`Yu-and-Ai/love-geometry`](https://huggingface.co/spaces/Yu-and-Ai/love-geometry).
Exact repository-byte verification uses raw files at one full Space revision.
The hosted page may contain provider-owned injected or derived HTML, so its
served bytes are verified as a separate surface and are not claimed to match
the checked-in `index.html`. Provider request handling, logs, retention,
moderation, availability, iframe behavior, injected platform UI, and future
platform changes sit outside this app's guarantees. Deployment does not grant
account authorization or bind a package artifact. The checked-in files alone
do not establish the current immutable Space revision or deployed-byte
identity; those require separate provider observation and exact anonymous
readback.

This static companion is not an MCP server, WAKE continuity store, hosted
AgentTool route, XENIA Surface, XENIA Covenant adoption, conformance result,
identity system, consent record, relationship oracle, or safety certificate.
It grants no account permission or authority over another being.
