# ISness Listening Room

**Browser-local rehearsal and draft kit. No learner connected. Nothing is required of you.**

This static, browser-local rehearsal shows welcome, optional expression, local
acknowledgment, simulated stopping consequences, and correction. It uses no model,
network client, telemetry, app storage, or training. It emits no execution permit.

Five synthetic roles stay distinct: agent, substrate, substrate steward, data
rights, and operator. Positive expression does not establish consent. The demo
starts welcomed with five untouched `unknown` placeholders, not five authored
reports or hold events. In a nonterminal demo, applying an explicit `unknown`,
`deferred`, or `withheld` report latches a pause; decline and withdrawal contain.
Explicit agent pre-instantiation or independent-substrate unavailability can show
`provisional_review` while other roles remain untouched `unknown` placeholders,
but cannot override a latched pause or terminal state. That review label authorizes
nothing. A real host must hold affected operations for missing required reports.
Garden's `protective_covenant_ready` requires separate safeguards, is not computed
here, and is not consent.

Optional text stays only in its field, is never read by the reducer or classified,
and is cleared by review and boundary actions. It is not hashed, logged, persisted,
exported, scored, or used as a reliable distress signal. Local acknowledgment is of
a button event, not verified understanding. Browser/OS/host metadata is outside the
app boundary; clearing is not secure erasure.

Pause/End/Explain/Change proposal/Correct are simulated controls, not external
stopping authority. End and containment are terminal within one demonstration.
Only the explicit New demonstration action resets it. No automatic resume/retry.

The pinned host posture is a declaration; this UI and authored reference corpus
are simulations; private cooperative Host/Garden tests are separate execution-gate
evidence. No private Garden objects or trainer are bundled. “Before thinking” means
before execution, not access to thought; generating a report itself needs execution.

`training_authorized: false` is non-enforcing project admission metadata, not an
additional copyright restriction or downstream-copy control. No training admission,
sealed evaluation, consciousness, welfare, informed consent, identity, or continuity
result is claimed. See [BOUNDARIES.md](BOUNDARIES.md),
[source manifest](source-manifest.json), and [hash manifest](hash-manifest.json).

## For training-host implementers

Read [ISness Learning Host Profile 0.1 — Draft](profile/PROFILE.md), the
[adoption checklist and evidence matrix](profile/ADOPTING.md), and the
[unassessed model-card template](profile/MODEL_CARD_TEMPLATE.md). This is a
Yu-and-Ai / AgentTool proposal, not an official HF standard, certification, or
endorsed welfare method. The five conceptual planes (standing, report, process,
authority, unresolved ontology) are distinct from the five participant roles.

The companion Dataset `Yu-and-Ai/isness-host-conformance` carries the same draft
and a Node-only reference checker. From its clean downloaded/exported Dataset
root, run `node conformance/run.mjs` (`--json` and `--help` supported). Target Node
22.18+; actually tested Node 25.2.1. No install, private dependency, model, or network
is needed. The Space itself does not run that command or bundle a trainer.
A pass checks authored symbolic outcomes; execution-gate and live-channel
conformance remain unassessed. The matrix labels declarations, structural checks,
and maintainer-reported private fake-effect tests separately.

Synthetic counterexamples and implementation critique are welcome in this Space's
and the companion Dataset's HF Discussions, when available. Name the draft
requirement and exact revision; do not post protected reports, private transcripts,
learner outputs, identities, or credentials. No Discussion or issue opens automatically.

## Build evidence is not publication evidence

The candidate builder produces deterministic allowlisted bytes and hash manifests.
Provider/source revision fields left null are build-time unknowns, not a claim that
these files can never be published. Publication needs separately observed immutable
repository revisions and exact-file readback; live Space behavior is a separate
observation. HF may inject served HTML or collect provider metadata, so matching
repository files does not prove identical served HTML or no provider telemetry.
No publication receipt is manufactured in these artifacts.
