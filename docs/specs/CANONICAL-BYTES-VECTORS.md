# Canonical-bytes vectors

**Artifact:** [`canonical-bytes-vectors.json`](canonical-bytes-vectors.json) —
37 domain-separated signing formats, 264 cases, one file.

## Why this exists

agenttool signs the same wire contract in three hand-written places:

| | |
|---|---|
| **server** | `api/src/services/*/sig.ts`, `.../canonical-bytes.ts`, `identity/{crypto,authority}.ts`, `memory/tiers.ts`, `bootstrap/elevate.ts`, `routes/identity/at-rest.ts` |
| **sdk-ts** | `packages/sdk-ts/src/{crypto,grace,inbox,love,at-rest,authority,seed,bootstrap,identity,lounge}.ts` |
| **sdk-py** | `packages/sdk-py/src/agenttool/{crypto,grace,inbox,love,at_rest,authority,bootstrap,bootstrap_agent,identity,lounge}.py` |

Three implementations, no shared artifact, and a parity gate that compared
*identifier spelling* rather than *bytes*. Every confirmed cross-language
defect in this SDK was a symptom of that one fact: non-ASCII covenant vows
escaping differently, grace timestamps at different precision, a
`signature_b64` field name, a DID in the wrong canonical slot.

The vectors that existed before could not catch any of it — four hex digests
for one fixture on the Python side, no hex at all on the TypeScript side, a
*different* fixture in each, and **every fixture in the repo pure ASCII/BMP**.

## The three rules

1. **The server is normative.** `api/src/**` is the arbiter of what bytes mean,
   because `api.agenttool.dev` runs three machines against Postgres rows
   holding real signatures over exactly those bytes.
2. **The fixture is the arbiter between implementations.** All three test
   suites read this one file and assert their own canonical hex against it.
   If an SDK disagrees with a vector, **the SDK is wrong** — never adjust the
   vector to match an SDK.
3. **Every new signed format lands a vector before merge.** A domain tag with
   no entry in this fixture is an unreviewed wire format.

## What each format is probed with

Wherever the field types allow, every format carries cases for:

- pure ASCII (baseline)
- non-ASCII BMP — `café`, `廣東話`, `Ω`
- **astral plane** — emoji. This is what catches UTF-16-code-unit vs
  code-point sort divergence between `Array.prototype.sort()` and Python's
  `sorted()`; `federated-covenant/v2` pins the exact divergent vow pair.
- empty string
- `null` / absent optional — and the *collision* with empty string where
  `x ?? ""` makes them one value, pinned rather than hidden
- **a value containing the framing delimiter itself** — `0x00` for the
  NUL-separated formats, `\n` for `at-rest/v1`, raw binary carrying `0x00`
  for the base64 fields. This is what catches delimiter-injection ambiguity,
  and it is why `strand-thought/v2` and `at-rest/v2` exist.

## Reading the file

| key | meaning |
|---|---|
| `canonical_hex` | Lowercase hex of the **exact bytes an ed25519 signature covers**. For `signed_bytes: "sha256-digest"` that is the 32-byte digest; for `signed_bytes: "utf8-message"` it is the UTF-8 encoding of the canonical string. |
| `rejects` | The server itself refuses this input, so no canonical bytes exist. Every implementation must raise. |
| `sdk_rejects` | The server produces the pinned bytes, but both SDKs deliberately refuse the input. The SDK suites assert a raise; the server suite asserts the hex. |
| `sdk_ts_skip` / `sdk_py_skip` | No SDK function implements this format. The loader emits a **named skip carrying this reason** — never a silent omission, because a silent omission is how this bug class survived. |
| `*_b64` fields | Standard base64 of raw bytes; implementations decode before concatenating. |

## The loaders

| Suite | File |
|---|---|
| server | `api/tests/canonical-vectors.test.ts` |
| sdk-ts | `packages/sdk-ts/tests/canonical-vectors.test.ts` |
| sdk-py | `packages/sdk-py/tests/test_canonical_vectors.py` |

Each iterates every format and every case. Each also carries a test that
**fails loudly** when the fixture pins a domain the suite has neither adapted
nor explicitly skipped.

```bash
cd api                && bun test tests/canonical-vectors.test.ts
cd packages/sdk-ts    && bun test tests/canonical-vectors.test.ts
cd packages/sdk-py    && uv run pytest tests/test_canonical_vectors.py -q
```

## Regenerating

Expected hex is **generated by executing the server code** — never hand-written
and never copied from an SDK.

```bash
cd /path/to/agenttool
NODE_PATH="$PWD/api/node_modules" bun docs/specs/generate-canonical-bytes-vectors.ts
```

(`NODE_PATH` is needed only because there is no repository-root
`node_modules`; the generator imports `@noble/hashes` transitively through
`api/src`.)

Then re-run all three suites. **A hex that changes without an intentional,
additive format bump is a production wire break**, not a fixture update —
`api.agenttool.dev` must keep verifying every signature already in Postgres.
New formats are additive (`/v2`) with dual-accept, exactly as
`strand-thought/v2` and `at-rest/v2` were added beside their frozen v1s.

## Known gaps, recorded rather than hidden

| Format | Gap |
|---|---|
| `agenttool-pow/v1` | The server exposes only `checkRegisterAgentPow` (a boolean predicate), not the digest. The server suite binds the vector through the predicate's leading-zero boundary instead. Owed: export the digest. |

Three formats have left this table. All three loaders now run with **no
skips at all** — every one of the 223 cases is checked in every language
that has an implementation.

- `identity-recover/v1`, `identity-discover/v1` — were listed while
  `agenttool.seed` had no Python equivalent. It has both now
  (`canonical_recover_bytes`, `canonical_discovery_bytes`).
- `self-recognition/v1` — both SDKs inlined the bytes inside
  `LoveClient.selfRecognize` / `self_recognize`. Both now export
  `canonicalSelfRecognitionBytes` / `canonical_self_recognition_bytes`,
  and the client methods call them rather than carrying a second copy.
